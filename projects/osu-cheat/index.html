andrew kim / projects / osu bot

a bot that plays osu! on its own. it follows the song by reading the game's memory, parses the map to know where every note is, and presses the keys to hit them in time. it works for standard, as a relax bot that taps while you still aim, and for mania at every key count.

osu! can catch this. the keys go through sendinput and the timing it produces is far more even than a person's, so a score it sets online gets flagged and takes the account with it. don't run it signed in.

finding the game in memory

the bot needs the song's clock, the current map, and whether a map is even playing, and osu! doesn't expose any of that. it has to read it out of the game's memory. the addresses move whenever osu! updates, though, so hardcoded ones would break on the next update.

so it does what a memory scanner does. for each value, it searches the running process for a short, stable pattern of bytes from the machine code near where osu! touches that value, then reads the pointer sitting at a fixed offset from the match. the ?? bytes are wildcards, for the parts that do change between builds.

after that, reading the clock is one memory read. audio_time() returns the milliseconds osu! is into the song.

reading the map

.osu files are plain text split into sections. the parser pulls out the hit objects and converts each one into a timestamp. for standard it walks the timing points to turn a slider's length into a real duration. for mania it maps each note's horizontal position into a column with x * keys / 512, since the format stores columns as x coordinates across a 512-wide playfield.

playing in time

the rest is staying in sync. the notes are sorted by time, and the bot holds an index into them. each tick it reads the song's current time from memory and fires every note whose time has passed. if you skip ahead or retry, the clock jumps backwards, so it finds its place again with a binary search and lets go of anything it was holding.

pressing the keys

keypresses go through the windows SendInput api as scan codes. in standard the bot alternates between two keys. in mania each column gets its own key, and long notes stay held until their end time. pressing end stops everything.
